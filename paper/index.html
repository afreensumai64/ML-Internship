Content Opportunity Scoring for Review Prioritization

A reproducible analysis for ranking pages that may warrant content review using observable search, traffic, and freshness signals.

1. Abstract

This research asks whether observable page-level signals can be used to rank pages for content review. The analysis uses February 2026 page-level search and content information from the FlyRank internship warehouse and evaluates an interpretable Logistic Regression model against a transparent rule-based baseline. The observed March outcome proxy is whether a page recorded zero GSC clicks during the evaluation window. On the held-out evaluation set, the model and baseline are compared using Precision@50 and Average Precision. The resulting ranking is intended as decision support for prioritizing human review, not as an automatic content decision or a causal claim about search performance.

2. Introduction / Problem Statement

Content teams may have many pages that could potentially require review, while available editorial resources are limited. A repeatable ranking approach can help organize which pages should be inspected first.

The research question is: Can observable page-level search, traffic, engagement, freshness, and performance signals be used to rank pages for review so that limited content resources can be focused on the most relevant opportunities first?

3. Data

Dataset: FlyRank internship warehouse, release v20260703.

The analysis uses:

  • fact_content_daily_performance
  • dim_content

February 2026 provides the decision-time features. March 2026 provides the observed evaluation outcome. June 2026 is treated as a sealed warehouse month and is not used for model development.

The model uses GSC impressions, GSC clicks, and content age in days. Future information, label-derived variables, product-generated priority or health fields, client information, private queries, credentials, and raw exports are excluded.

4. Methodology

Logistic Regression was selected because the objective is to create an interpretable ranking of pages for human review.

The observed March outcome proxy, went_dark, equals 1 when observed March GSC clicks are zero and 0 otherwise. This is an observed outcome proxy and is not treated as ground truth for successful content refresh.

The Week-4 baseline uses content age and February GSC impressions to produce a transparent score from 0 to 4.

Validation uses an 80/20 grouped train-test split by client_hash_id, with random state 42. Both methods are evaluated on the same held-out population. Precision@50 is the primary ranking metric and Average Precision is also reported.

5. Results

The Logistic Regression model is compared with the Week-4 transparent baseline on the same held-out evaluation population.

6. Limitations & Honest Framing

The analysis is observational and does not establish that refreshing a page will cause improved search performance. The March zero-click outcome is only a proxy and does not measure whether a refresh would succeed.

Low impressions or clicks may have legitimate explanations such as low search demand, seasonality, or intentional targeting. The model therefore provides a review signal rather than an automatic action.

The model uses only three verified features, and results are based on one held-out evaluation split. Performance may differ across other clients, periods, or future data.

7. Ranked Recommendations

The model ranking is translated into a human-review playbook. High-ranked pages can be inspected for freshness, relevance, visibility, and content-quality opportunities.

  • review_refresh: inspect freshness and content quality.
  • review_visibility: inspect search visibility and alignment.
  • monitor: retain for monitoring rather than immediate review.

8. Reproducibility

The analysis is implemented in the repository's capstone notebook. The notebook contains the data construction, feature definitions, validation design, baseline calculation, model training, evaluation, leakage checks, and recommendation generation.

The workflow can be rerun using the documented FlyRank warehouse release, February feature window, March evaluation window, grouped 80/20 split, and fixed random state of 42.
